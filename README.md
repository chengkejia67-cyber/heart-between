# 心间 · BETWEEN US

一个适配手机、平板和电脑的感情态度探索网站。通过 64 道四选项情境题，生成八维画像、整体解读、组合洞察和沟通建议。

**GitHub Pages 站点：** https://chengkejia67-cyber.github.io/heart-between/
**题库版本：** 2.0.0 · **应用版本：** 2.0.0

## 功能

- 64 道完整情境题，支持上一题、跳题、补答和修改。
- 浏览器本地保存；刷新恢复当前位置，报告可刷新重看；支持浏览器返回与跨标签页同步。
- 八维报告：占有欲、边界感、确定感需求、亲密需求、情感独立性、情感表达、冲突修复、长期承诺。
- 吃醋感受与干预行为分开计分；自我边界与尊重他人边界分开解读。
- 9 个情境偏好标签：分别解释异地、分歧、投入、纪念日等选择，不做高低排名。
- 无效或不足的答题样本进入补答，不填造分数。
- 示例报告不覆盖真实答题记录。
- 分享测试首页、PNG 画像卡预览与下载、手机长按保存、完整报告打印。
- 无账号、无后端、无第三方字体或分析 SDK；答案与反馈不上传。

本产品用于自我探索。题库与规则尚未经心理测量验证，不能用于诊断、判断忠诚度或预测关系结局。

## 开发与测试

Node.js 24 或以上。项目无运行和构建依赖，无须执行 `npm install`。

```sh
npm test
npm run build
npm run preview
```

生产预览：http://127.0.0.1:8766/ 。开发源文件预览使用 `npm run dev`。端口可用 `PORT` 环境变量或 `node scripts/serve.mjs --port 8888` 指定。

没有 npm 时，可直接使用：

```sh
node tests.mjs
node --test tests/*.test.mjs
node scripts/build.mjs
node scripts/serve.mjs
```

## 发布

仓库 `.github/workflows/pages.yml` 在 `main` 推送后自动执行：

1. 检查计分、记录恢复、路由与生产构建。
2. 生成 `dist/`，将 JavaScript 和 CSS 以内容哈希命名。
3. 上传网站产物并部署到 GitHub Pages。

拉取请求只运行检查，不进行发布。仓库 Settings → Pages → Source 应设为 **GitHub Actions**。工作流通过时才部署；源文件、需求文档与测试不进入网站发布产物。

所有资源使用相对路径，支持 `/heart-between/` 这样的 GitHub 项目子路径。路由采用 `#/question/1`、`#/report`、`#/example`，刷新时不依赖服务器重写规则。URL 不携带答案和分数。

Pages 的访问可达性取决于访问者的网络环境。若未来需要域名、用户账号或跨设备同步，可分别扩展部署配置和后端，不必改动当前题库结构。

## 代码结构

| 文件 | 职责 |
| --- | --- |
| `questions.js` | 64 道题目、选项、分值、维度、版本 |
| `model.js` | 样本门槛、计分、类型、组合解读 |
| `progress.js` | 记录清洗、版本兼容、路由编解码 |
| `app.js` | 页面、答题交互、报告与图片导出 |
| `bootstrap.js` | 页面加载与失败重试 |
| `styles.css` | 响应式布局、可访问焦点与打印样式 |
| `scripts/build.mjs` | 无依赖、内容哈希、白名单生产构建 |
| `scripts/serve.mjs` | 本地 HTTP 预览，非永久公网托管 |
| `tests.mjs`、`tests/` | 计分、记录、路由和构建测试 |
| `docs/` | PRD、完整题库与发布说明 |

## 数据和版本

存储键沿用 `between-us:v1`，题库 1.0.0 的旧记录会提示重新作答，不会套用新版选项。记录格式为 schemaVersion 2。恢复时仅接受当前版本、已知题目 ID 和合法选项；损坏或旧版本记录不会用于新报告。

localStorage 不可用时仍可完成当前会话，并显示无法保存的提示。清除记录需确认；跨标签页清除会同步到其他已打开页面。换域名、换浏览器或换设备无法自动恢复旧记录。

共享按钮只分享站点首页；画像卡包含用户主动导出的摘要；本机反馈不发送给维护者。托管平台可能保留常规访问日志。

题库或选项顺序变更时需更新 `questions.js` 中的 VERSION，避免旧索引映射到新题。发布文案或样式变更仅需更新应用版本。哈希资源避免静态缓存混用版本。
