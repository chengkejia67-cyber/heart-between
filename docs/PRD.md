# 心间 BETWEEN US｜产品 PRD V2.0

日期：2026-11-06。应用版本与题库版本均为 2.0.0；本版落实用户确认的逐题复盘方案。

## 1. 产品定位

通过 64 道四选项情境题，帮助成年人理解自己在关系中的态度，生成八维画像、整体分析与具体情境解读。借鉴类型测试的参与感，不使用 MBTI 分类，不将结果作为心理诊断、忠诚度判断、配对成功率或人格优劣排名。

适用于不同性别、性取向和恋爱经历的人。没有相关经历时可想象双方自愿的关系；无法判断时可跳过。题库与分界值尚未经过心理测量验证。

正式网站：https://chengkejia67-cyber.github.io/heart-between/ 。同一链接适配手机、平板和电脑，无需安装或登录。

## 3. 选项与解读原则

四选项应覆盖不介意、介意、生气、要求改变、撤回投入、难以接受等真实态度，避免所有选项都要求平静、大度或完整沟通。选项保持审阅确认的固定顺序，不重新轮换。

1. 情绪与行为分开：生气不等于失去独立判断；吃醋不直接等于干预。
2. 请求与强迫分开：希望删除旧照片或考虑结束关系，不直接计为侵犯隐私或持续施压。
3. 尊重拒绝不要求心情平静：失落、抱怨但最终接受，与明确越过拒绝区别计分。
4. 同分允许存在：语言、行动、先解释后修复等选择可以同分，不以措辞更漂亮评为更高。
5. 无法可靠排序的态度只生成标签：不将拒绝异地、要求互惠或设定底线判为不愿经营关系。
6. 具体行为信号补充数值：同样的表达主动性可能带有焦急；报告据实说明，不称其沟通能力更优。

## 4. 用户流程

首页 → 开始或继续 → 64 道题 → 有效样本校验 → 个人报告；不足时进入补答总览。

示例入口单独使用固定答案，不覆盖个人进度。已完成者返回首页看到“查看我的报告”。重新探索需确认清除本机记录。

- 首页：品牌、关于测试、示例报告、开始按钮、维度介绍与 FAQ。
- 答题：一屏一题、情境前提、四选项、上一题/下一题、跳过、已答与已浏览数量。选择后不自动跳题。
- 补答：64 个题号可跳转，未答/跳过显著标记；显示不足的维度，提供返回总览按钮。
- 报告：类型与摘要、整体解读、雷达图、八维详细解释、边界子项、干预子项、表达方式、具体情境标签、组合洞察、优势与练习、沟通句式、导出分享、反馈与量尺说明。

## 5. 量尺与有效样本

| 维度 | 主计分题 | 最少有效回答 | 口径 |
| --- | ---: | ---: | --- |
| 占有欲 | 4 | 3 | 在意特殊位置与潜在竞争的程度 |
| 边界感 | 8 | 6 | 自我边界与尊重他人边界各 4 题，分别至少有效 3 题 |
| 确定感需求 | 6 | 4 | 对明确回应、身份与告知的需要 |
| 亲密需求 | 8 | 5 | 期待陪伴与分享的频率 |
| 情感独立性 | 8 | 5 | 个人生活重心、自我判断及支持来源 |
| 情感表达 | 6 | 4 | 主动让喜欢、不满与需要被知道 |
| 冲突修复 | 5 | 4 | 是否回到问题、重启沟通与尝试调整 |
| 长期承诺 | 5 | 4 | 当前对持续关系与共同方向的意愿 |

64 题由 50 道主计分、4 道干预行为、8 道态度标签、1 道表达方式、1 道纪念日偏好组成。每个维度题组仍有 8 题，但不是所有题都进入该主分数。

`展示值 = round(有效题得分总和 ÷ 有效题数 ÷ 3 × 100)`

跳过、未答、非法索引不计入分母。分数属于内部量尺，非百分位或概率。部分题目最低分不为 0，不强制将每个维度拉伸到 0–100 全范围。0–34、35–65、66–100 分别用于较低、中间、较高倾向文案，不代表好坏。

生成完整报告需浏览全部 64 题且八维满足门槛。干预行为独立要求 3 / 4 题，不足时显示信息不足，不阻止主图；具体已选行为仍可作场景提示，不据此补造辅助分数。

## 6. 标签与报告规则

第 24、31、40、43、47、55、56、59 题不计入主图，分别保留异地与现实选择、分歧中的取向、投入前的考虑、约定变化、重复问题的处理、冲突后的恢复节奏、生活调整原则、让人安心的回应等具体情境选择。第 62 题为纪念日偏好，也不计分；报告最多显示 9 张情境卡，跳过时不生成对应卡片。第 54 题单独决定表达方式。

类型标题依次匹配：亲密高且独立高→自在相拥；确定需求高且表达低→含蓄共鸣；承诺高且修复高→温柔建设；独立高且亲密低→留白同行；亲密高→热忱靠近；承诺低→当下感受；其他→平衡探索。干预行为高于 65 时覆盖为“连接探索型”。标题只是摘要，不是固定身份。

主图、标题不受名义标签选择影响。整体解读综合亲密、确定感/表达、未来意愿，并补充异地态度。规则文案同时考虑具体信号：生气但认可自己、急于表达、先防御后修复、照片接受底线等。选择了越界行为时，不因均分较低就赞许为“尊重选择”。

## 7. 视觉与响应式

暖白背景、深灰绿文字、珊瑚红主按钮，配浅绿和淡紫卡片；宋体标题与系统无衬线正文。页面沿用已确认设计，不加载外部字体。

- 桌面主容器最大 1180px；答题左侧章节导航、右侧题卡。
- 720px 以下采用单列答题/报告、两列维度简介。
- 检查 320、390、768、1440px 的首页、答题和报告，均应无横向溢出。
- 原生单选、可见焦点、对话框焦点约束、Escape 关闭、页面标题读屏可达。
- 支持减少动态效果；打印隐藏导航、按钮和反馈，保留完整解读。

## 8. 数据与版本

所有答案、分数、报告和图片在浏览器生成，无答题服务器。localStorage 键继续为 `between-us:v1`，记录包含题库 version、schemaVersion、answers、index、feedback、updatedAt。

题库升级至 2.0.0，旧 1.0.0 索引不得套用新版选项；读取旧记录时提示重新作答。合法同版进度可恢复，损坏字段过滤；存储不可用时当前会话仍可答题并提示限制。

路由使用 `#/question/17`、`#/report`、`#/example`、`#/review`，支持刷新与浏览器前进后退；同源标签页同步记录。更换设备或浏览器不迁移进度。

分享仅含首页链接，不携带答案和报告。PNG 卡片只含用户主动导出的摘要；反馈仅本机保存。托管平台可能保留常规访问日志。清除本机记录不会删除用户已下载或分享的图片。

## 9. 实现与发布

原生 HTML/CSS/JavaScript ES Modules；Node.js 24 执行测试与无依赖构建。questions.js 管理题库，model.js 负责评分与解读，progress.js 管理记录与路由，app.js 管理展示与交互。

GitHub Actions 在 main 推送后运行测试、构建哈希资源、部署 GitHub Pages。发布目录只包含网站文件，不包含文档、测试与源代码工具。所有引用使用相对路径以支持仓库子路径部署。

本地：`npm test`、`npm run build`、`npm run preview`；无 npm 时使用 README 中的等效 Node 命令。
