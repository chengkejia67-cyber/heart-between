# 心间 BETWEEN US｜感情态度探索产品 PRD

版本：V1.0 设计基线 · 2026-11-06

> 本文保留已确认的产品设计口径。当前应用为 V1.1，GitHub Pages 发布、路由恢复与新增实现见 [RELEASE.md](RELEASE.md)；启动与部署以仓库 README 为准。

交付范围：响应式网站、64 道完整题库、规则计分、八维报告、分享图片、本地进度、实现源码。
文档状态：可运行产品原型；题目及分界值尚未经心理测量验证。正式对外推广前需开展理解度试测及测量评估。

## 1. 产品摘要

**一句话定位：从真实生活情境出发，帮助用户理解自己如何靠近、表达、处理分歧与期待未来，生成一份可以用于沟通的感情态度说明书。**

产品借鉴 MBTI 的参与感，以及参考图片中“类型标题＋整体解读＋维度图”的结构；采用独立维度、题库和文案规则，不使用 MBTI 的类型或测量结论。类型名只是方便记忆的摘要，连续维度与行为解读才是报告主体。

品牌名为暂定名称「心间 / BETWEEN US」，正式商用前需确认品牌与域名可用性。

## 2. 目标用户与使用场景

- 希望理解自己感情偏好的成年人，不预设性别、性取向、婚姻意愿或恋爱经验。
- 单身用户：可以依据最近的倾向和理想关系作答；没有经验可跳过情境。
- 处于关系中的用户：通过具体结果讨论陪伴、边界、回应与未来期待。
- 分享用户：展示自己的画像摘要，或邀请对方打开同一测试首页。

不用于诊断、关系忠诚度判断、配对成功率、伴侣评分、人格优劣排名或预测分手。题目以双方自愿且不存在已知危机的普通关系情境为基础；遇到不适用的前提允许跳过。

## 3. 用户价值与产品目标

1. 用户能够指出至少两项与自己有关的关系需求。
2. 结果不仅给出形容词，还能解释“具体怎么想、怎么做、可能怎样被理解”。
3. 给用户一句可直接用于沟通的话，以及一项可执行的小练习。
4. 手机、平板、电脑使用同一链接，无须安装或登录。
5. 完成体验包括：进入、答题、离开后续答、补答、生成报告、导出图片、分享首页。

Demo 验收以流程可用性和解释一致性为目标，不宣称测量有效性。后续运营指标应通过用户研究与获授权的统计建立基线。

## 5. 信息架构与页面流程

首页 → 开始 / 继续探索 → 64 题 → 完成校验 → 个人报告。
校验失败 → 补答页 → 点击题号修改 → 返回补答总览或回到最后一题生成报告。
首页 → 示例报告 → 开始 / 继续自己的探索。
报告 → 下载画像卡 / 分享测试首页 / 重新探索。

### 5.1 首页

- 品牌导航：心间、关于测试、产品 PRD。
- 主标题：“爱有很多种，你是哪一种？”
- 主按钮：无进度时“开启我的探索”；有有效回答时“继续我的探索”。
- 次按钮：先看看示例报告，始终标记为示例。
- 信息：64 个日常情境、约 10–15 分钟、无需登录；时间为产品估计，需试测后校准。
- 八维说明、测试立场、常见问题、隐私与清除数据入口。

### 5.2 答题页

- 一屏一题，四个行为选项均可点击整个区域。
- 题目前标记情境类型与适用前提；不显示具体计分方向。
- 单选后不自动跳题，避免误触与读屏焦点跳动。
- 展示当前题号、已回答数量与已浏览进度，三者含义不同。
- “无法判断”跳过，不记为中间分或 0 分。
- 上一题与回看保留选中状态；修改会覆盖该题原答案。
- 每次选择及前后导航保存本地状态。
- 最后一题触发完整性校验。
- 桌面侧栏提供四段旅程提示，每段 16 题；段落为进度文案，题目仍交错覆盖全部维度。

### 5.3 补答页

- 显示已回答数量、需要补充的维度、64 个可点击题号。
- 已答题用浅绿，未答或跳过用浅橙；按钮同时提供文字语义。
- 无足够样本时不编造完整雷达图、不用平均分填补缺失值。
- 已浏览所有题且达标后可生成报告；从补答页进入题目时提供“返回补答总览”入口。

### 5.4 结果页

顺序为：类型标题 → 一句话摘要 → 整体解读 → 八维雷达图 → 8 项详细解释与子项 → 多维组合分析 → 相处优势与小练习 → 沟通句式 → 导出与分享 → 本机反馈 → 量尺说明。

- 每个维度显示整数 0–100、两端含义、有效题数与说明。
- 数字是内部量尺，不是人群百分位或行为概率。
- 雷达图面积不代表好坏；不计算恋爱能力总分。
- 报告文案采用“可能”“倾向”等有边界的表达，基于自述且会随阶段变化。
- 不展示“绝配类型”“渣男/渣女”“爱得深所以控制”等结论。

## 6. 维度与测量口径

| 维度 | 主量尺 | 特殊处理 |
| --- | --- | --- |
| 占有欲 | 对特殊地位和潜在竞争的情绪敏感度 | 4 道情绪题计入雷达；另 4 道干预行为题单独计分，绝不以干预行为解释爱意 |
| 边界感 | 表达自身界限与尊重他人界限 | 4 道自我边界＋4 道尊重边界；总分仅概览，两子项必须分别达标并展示 |
| 确定感需求 | 对关系身份、明确回应和告知的需要 | 8 道题；高分不直接等于心理不安全 |
| 亲密需求 | 陪伴、联系和生活分享的期待频率 | 8 道题；与独立性分别测量 |
| 情感独立性 | 个人生活重心与部分情绪自我调节 | 8 道题；不将压抑或拒绝支持解释为成熟 |
| 情感表达 | 主动让喜欢、委屈与期待被知道 | 6 道表达主动性题；2 道表达方式题仅生成标签 |
| 冲突修复 | 分歧后重启沟通、协商与落实的倾向 | 8 道题；暂停不等于惩罚性失联 |
| 长期承诺 | 当前阶段对持续经营和共同方向的意愿 | 8 道题；不以结婚、生育为唯一长期目标 |

合计 64 题：主图计分题 58 道（4＋8＋8＋8＋8＋6＋8＋8），干预行为辅助题 4 道，表达方式标签题 2 道。每个维度题组均为 8 道。

### 6.1 四选项原则

- 优先使用日常情境、内心反应、实际行动与合理需求的取舍。
- 同题选择尽量处于同一语义层级，避免把情绪、行为、价值判断混在一条排序中。
- 同题选项允许同分；如尊重拒绝的两种表达方式可以同分。
- 名义类别不强行排序；表达方式使用标签，不参与表达程度分数。
- 使用稳定的题目 ID，不能按显示位置推断计分。
- 当前选项按题序确定性轮换，避免 A 始终低、D 始终高；不是针对每个用户随机。
- 每 8 题包含每个维度的一题，以交错方式降低维度猜测。
- 当前草案中部分选项仍存在社会赞许性与单调性，正式版应根据访谈和数据修订，不能仅靠轮换消除。

### 6.2 计分与缺失

有序选项使用预设 0–3 分，均分转换公式：

`维度展示值 = round(有效题得分总和 ÷ 有效题数 ÷ 3 × 100)`

跳过、未答、非法索引均视为缺失，不进入分母。表达方式标签题不进入主图计分。

| 项目 | 最少有效回答 |
| --- | ---: |
| 占有欲主量尺 | 3 / 4 |
| 占有欲干预行为子项 | 3 / 4；不足时单独显示“信息不足”，不阻止其他主量尺成图 |
| 边界感 | 自我边界 3 / 4 且尊重边界 3 / 4；总计至少 6 / 8 |
| 情感表达主量尺 | 4 / 6 |
| 其他主维度 | 每项 5 / 8 |
| 表达方式标签 | 无最低门槛；无答案时显示信息不足；不同答案时显示随情境变化 |

生成报告还需浏览全部 64 题，避免中途作答就生成完整结论。阈值只是 Demo 规则，并非经验标准。

展示分段：0–34 为较低倾向，35–65 为中间倾向，66–100 为较高倾向。分段不等于好坏，也不表示诊断界限。

### 6.3 边界与占有欲的解释限制

- 边界总分可能掩盖子项差异，组合解读优先使用子项；用户必须能看到两项数值。两子项差距至少 25 分时，维度文案优先解释差异，不依据总分断言两项都强。
- 占有欲主分数不混入查看隐私、施压、限制交友等行为题。
- 干预行为倾向大于 35 时出现“将不安转化为请求而非限制”的说明。
- 干预行为倾向大于 65 时使用中性标题“连接探索型”，避免奖励或浪漫化干预行为。
- 若干预行为子项不足，不生成相关行为结论。
- 不根据“少吃醋”推断不爱，根据“多陪伴”推断不独立，根据“表达较少”推断没有感情。

## 7. 类型与组合报告引擎

报告由本地规则和审阅过的文案模块生成，无远程大模型请求、无随机结果。相同题库版本与相同答案应得到相同结果。

### 7.1 类型标题的优先规则

1. 亲密需求 > 65 且独立性 > 65：自在相拥型。
2. 确定需求 > 65 且表达 < 35：含蓄共鸣型。
3. 长期承诺 > 65 且修复 > 65：温柔建设型。
4. 独立性 > 65 且亲密需求 < 35：留白同行型。
5. 亲密需求 > 65：热忱靠近型。
6. 长期承诺 < 35：当下感受型。
7. 其他：平衡探索型。
8. 最后覆盖规则：干预行为 > 65 时标题为连接探索型。

这些标题是摘要规则，不是穷尽所有人的固定性格分类。应允许未来更新命名，且持续展示实际维度。

### 7.2 多维组合洞察

- 亲密高＋独立高：享受陪伴，同时保有个人重心。
- 占有高＋尊重边界高＋干预低：会吃醋，也能尊重选择。
- 确定需求高＋表达低：期待回应，却可能未明确表达需要。
- 自我边界低＋尊重边界高：容易顾及对方，需要练习表达自己的界限。
- 长期意愿高＋修复低：希望关系持续，也需要可执行的修复方式。
- 干预行为 > 35：说明施压与越界的局限，建议请求与协商。
- 无命中时：说明情境差异和进一步自我观察，不虚构独特洞察。

整体解读由亲密重心、确定感与表达、未来意愿三段构成；另生成优势、练习和沟通句式。每段都有可追踪的触发条件。复杂规则下一版应采用单独 JSON 规则表，并建立反例集。

## 8. 视觉与交互规范

设计方向：温暖、安静、轻盈的编辑式页面。参考图的长文解读与画像结构予以保留；品牌、排版、图形和配色独立设计，不照搬参考品牌或文案。

- 背景：暖白 `#F8F6F0`；卡片：`#FFFEFA`。
- 主文字：深灰绿 `#303C36`；主按钮：珊瑚砖红 `#C85540`。
- 辅助色：浅鼠尾草绿 `#E8EEE1`、淡紫 `#EBE6F1`。
- 中文标题：系统宋体系列；正文：系统无衬线。无需外部字体请求。
- 圆角：8–15px；细边框；图表只作辅助，不以面积排名。
- 桌面主容器最大 1180px，正文与结果页保持较短行宽。
- 720px 以下为移动布局：首页纵向、维度卡两列、答题单列、报告单列。
- 721–1000px 优化平板：缩小间距和视觉物宽度。
- 最低支持目标宽度 320px；主按钮与选项触控区域大于约 44px。
- 使用原生 radio、键盘焦点、对话框焦点约束、读屏标题与数值说明。
- 尊重减少动态效果偏好；不做强制计时、虚假分析进度或诱导分享。

## 9. 状态与数据设计

前端静态应用，文件分工：

- `questions.js`：题库、维度定义、固定题目 ID、选项分数与标签、版本号。
- `model.js`：有效样本校验、均分计算、子项、报告规则和示例答案。
- `app.js`：页面、交互、本地存储、下载图片、分享和反馈。
- `styles.css`：响应式布局、键盘焦点、打印与减少动态效果样式。
- `index.html`：入口；不依赖第三方 CDN。

localStorage key：`between-us:v1`。

`{ version, answers: { [questionId]: 0|1|2|3|"skip" }, index, feedback, updatedAt }`

- 读取时校验版本、题目 ID、选项范围和题号。
- 版本不一致时不复用旧答案，防止题目修改后沿用错误计分。
- 存储不可用时仍能完成当前页面流程，并提示无法保存。
- 个人结果实时由答案计算，不额外持久化报告全文。
- 示例使用单独的固定答案集合，不写入个人答案。
- 页面状态采用前端内存控制；刷新后回到首页，通过继续按钮恢复。
- Demo 无跨设备同步；同一浏览器同一来源下共用一份进度。

## 10. 分享、数据与隐私

- 分享按钮只提供测试首页 URL，不在参数、路径或 fragment 中携带个人分数或答案。
- 优先调用浏览器系统分享；不支持时复制链接；复制失败时显示可复制地址。
- 图片通过 Canvas 在本地生成 PNG，包含类型、摘要、八维图和量尺说明，不包含原始答案。
- 示例图片始终标记“示例画像”；用户下载行为是显式操作。
- 用户可在页脚清除当前来源下本产品的答案、进度、反馈；二次确认以避免误操作。
- 当前反馈仅本地保存，不宣称已发送给产品团队。
- 不引入广告 SDK、远程分析、第三方字体或追踪脚本。
- 托管层可能保留普通访问日志，不能宣称整个访问过程完全无日志。
- 图片一旦由用户下载或分享到外部，清除本机记录不会删除外部副本。

## 11. 技术方案与发布方式

采用原生 HTML、CSS、JavaScript ES Modules，无构建依赖。适合静态托管；所有题库和报告规则在客户端公开，不属于保密模型。

本地运行：在项目目录执行 `python3 -m http.server 8765 --bind 127.0.0.1`，打开 `http://127.0.0.1:8765`。不能直接双击 HTML 作为完整模块运行方式，应使用 HTTP 服务。

本次可提供临时公网 HTTPS 预览：仅转发 Demo 静态目录，由本机 HTTP 服务和临时隧道共同提供。该链接适合评审，不是永久部署；电脑休眠、服务退出或隧道失效时不可用。若隧道不可用，本地链接仍可使用。

正式发布：将 `index.html`、`styles.css`、`app.js`、`questions.js`、`model.js` 和需要公开的文档上传至静态托管环境，绑定正式域名与 HTTPS，确认缓存策略、版本升级与服务可用性。无需数据库即可保持当前功能。中文用户群正式上线前应以真实网络环境验证可达性。

## 12. 测试与验收标准

### 12.1 逻辑

- 恰好 64 题、8 个维度，每组 8 题，每题 4 个选项，ID 唯一。
- 相同答案、同一版本得到相同结果；展示轮换不改变语义分数。
- 有序选项的最低／最高答案得到对应 0／100；表达方式不改变表达主动性分数。
- 全部跳过不生成结果；有效题不足显示补答。
- 边界两个子项分别满足门槛，不能用一个子项替代另一个。
- 缺少干预行为答案时，不生成相关行为洞察。
- 组合规则与类型覆盖逻辑可验证，含高干预行为的反例。

### 12.2 功能

- 首页进入、选择、前进、返回、刷新续答、清除重测可用。
- 64 题完整提交后显示 8 项指标与整体报告。
- 示例浏览不覆盖已保存答案；示例导出图片有明显标记。
- PNG 可以下载并打开；分享仅包含首页 URL。
- 无控制台运行错误、无丢失文件、无未实现按钮。

### 12.3 响应式与可访问性

- 至少检查 320px、390px、768px 和 1440px 页面宽度。
- 首页、答题、结果页均无横向溢出。
- 键盘可以选择答案和操作按钮；对话框可用 Escape 关闭、Tab 不离开对话框。
- 核心结果不只通过颜色或图形传达；有文字标签与数值。
- 主要界面采用适合阅读的文字颜色；正式版应再执行完整 WCAG 审核。

具体执行结果记录在 `TEST-REPORT.md`，不以本节验收清单替代已执行证据。

## 13. 正式版研究与迭代

1. 先做约 8–12 人的理解度访谈，覆盖不同性别、恋爱经历和关系状态；记录难理解、强行选择和明显“正确答案”的题目。
2. 小规模试测后检查完成时间、流失位置、跳过率、极端作答比例、维度之间冗余与用户不认同的原因。
3. 题项若用于严肃测量，应由具备心理测量经验的专业人员评估信度、效度、公平性与分界方式；不能把用户觉得“很准”当成验证。
4. 当前题目为可运行草案，若进行题干、选项或计分修改，必须增加版本并保留版本记录。
5. 若启用统计，先明确收集内容与用户知情机制；尽量用聚合事件，不采集原始情感答案。
6. 双人版本优先呈现偏好差异与协商问题，不输出配对成功率、谁更爱谁或关系总评分。
